# Pilotes : trois agences en conditions réelles

Issue #82. La phase d'entretiens préalables n'a pas eu lieu. Le produit s'est
donc construit sans retour terrain — c'est le principal risque du projet, et
il ne se referme pas en écrivant du code.

**État au 8 septembre 2026 : aucune agence n'a encore fait passer un vrai
client par Onbo.** Tout ce qui suit est le protocole ; les conclusions se
remplissent après, pas avant.

## Ce qu'on cherche

| Critère      | Cible                                                    |
| ------------ | -------------------------------------------------------- |
| Nombre       | 3 agences                                                |
| Taille       | 3 à 30 personnes                                         |
| Marché       | France, agences web (site vitrine, e-commerce, refonte)  |
| Volume       | Au moins 2 onboardings clients par mois                  |
| Contrepartie | Usage gratuit pendant le pilote contre retours détaillés |

Une agence qui n'a pas de projet client qui démarre dans les trois semaines
n'est pas un pilote : c'est un avis, et un avis ne vaut pas un usage.

## Où les trouver

- Réseau direct et recommandations — le canal qui convertit le mieux à ce
  stade ;
- communautés d'indépendants et de studios (Slack, Discord, forums métier) ;
- agences déjà croisées en prestation, qui connaissent le problème.

Message d'approche : le problème (relancer un client pour ses accès et ses
contenus), pas la solution. Si le problème ne résonne pas, l'agence n'est pas
la bonne.

## Protocole

1. **Cadrer** (30 min, visio) : comment se passe leur onboarding aujourd'hui,
   avec quels outils, où ça coince. Noter les mots qu'ils emploient — ce sont
   ceux qui devraient être dans le produit.
2. **Installer** : créer leur espace, régler le branding, ne rien préparer
   d'autre. Ce qu'ils n'arrivent pas à faire seuls est le résultat.
3. **Observer** le premier onboarding de bout en bout, **sans intervenir**.
   Répondre aux questions seulement après coup. Une aide donnée sur le moment
   détruit la donnée qu'on est venu chercher.
4. **Débriefer** (45 min) à la fin du projet client : ce qu'ils ont fait hors
   de l'outil, ce qu'ils ont ré-expliqué à leur client, ce qu'ils feraient
   autrement.
5. **Décider** : reprendre l'ordre du backlog à partir de ce qui est remonté.

## Grille d'observation

À remplir pendant, pas de mémoire.

| Quoi           | À noter                                                                          |
| -------------- | -------------------------------------------------------------------------------- |
| Abandons       | À quel écran s'arrêtent-ils ? Combien de temps avant de renoncer ?               |
| Questions      | Ce qu'ils demandent — au produit, ou à nous                                      |
| Contournements | Ce qu'ils refont à la main, par email, dans un tableur                           |
| Vocabulaire    | Les mots employés pour « étape », « portail », « validation »                    |
| Côté client    | Le client a-t-il ouvert le lien seul ? A-t-il écrit à l'agence pour comprendre ? |
| Temps          | Délai entre l'envoi du lien et le premier dépôt                                  |
